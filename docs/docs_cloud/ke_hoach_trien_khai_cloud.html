1. Cloud cho người mới: 6 khái niệm cần nắm

Hiện code chạy trên máy của nhóm, chỉ người ngồi trước máy dùng được. Triển khai lên cloud là thuê máy chủ của nhà cung cấp để chạy code đó 24/7, có địa chỉ web công khai ai cũng mở được.

Khái niệmGiải thích ngắnTrong dự án này
Frontend / BackendFrontend là phần người dùng nhìn thấy trên trình duyệt. Backend là chương trình chạy trên máy chủ, nhận yêu cầu, xử lý rồi trả kết quả.Frontend: React. Backend: FastAPI (Python) chứa pipeline GraphRAG.
PaaS (Platform as a Service)Chỉ cần đưa code lên, nhà cung cấp tự lo máy chủ, hệ điều hành, mạng, HTTPS. Dễ hơn nhiều so với tự thuê máy ảo (IaaS) rồi cài đặt từ đầu.Render chạy cả frontend và backend.
Managed databaseCơ sở dữ liệu do nhà cung cấp vận hành: không cần cài, chỉ nhận một chuỗi kết nối (địa chỉ, tài khoản, mật khẩu).Supabase (PostgreSQL + pgvector), Neo4j AuraDB (đồ thị).
Biến môi trường / secretMật khẩu, API key không được viết vào code hay đẩy lên GitHub. Chúng được khai báo trên trang quản trị của dịch vụ, code đọc ra khi chạy.DATABASE_URL, NEO4J_URI, OPENROUTER_API_KEY…
CI/CD (tự động triển khai)Mỗi lần nhóm đẩy code mới lên GitHub, dịch vụ tự lấy code, build và chạy bản mới.Render tự deploy khi push lên nhánh main.
Cold start (khởi động nguội)Gói miễn phí tắt máy chủ khi không ai dùng. Người dùng đầu tiên sau đó phải chờ máy chủ bật lại.Render tắt sau 15 phút không có truy cập, bật lại mất khoảng 1 phút.

Docker (nên dùng): đóng gói code và mọi thư viện thành một "container" chạy giống hệt nhau ở mọi nơi. Nhóm viết một file Dockerfile, Render dùng file đó để build. Phần này cũng giúp báo cáo có nội dung cloud rõ ràng (container hóa).

2. Bài toán (mục 1 của báo cáo)

Đặt bài toán theo góc nhìn hệ thống phần mềm trên cloud, không chỉ là bài toán NLP. Thầy yêu cầu sản phẩm "xuất phát từ quá trình phân tích thiết kế hệ thống", nên cần có các sơ đồ ở cuối mục này.

Đầu vào
  • Câu hỏi tiếng Việt về luật giao thông đường bộ (mức phạt, điều kiện, thủ tục…)
  • Ngày áp dụng (tùy chọn, mặc định là hôm nay)
  • Phía quản trị: kho văn bản pháp luật đã xử lý (11 văn bản)
Đầu ra
  • Câu trả lời kèm trích dẫn đến Điều/Khoản/Điểm còn hiệu lực tại ngày hỏi
  • Danh sách điều khoản liên quan, xem được nguyên văn
  • Đồ thị liên kết (dẫn chiếu, sửa đổi) của điều khoản
  • Một địa chỉ web công khai, truy cập được từ mọi thiết bị
Cốt lõi
  • Đưa pipeline GraphRAG thành dịch vụ web nhiều người dùng đồng thời
  • Chạy được trong giới hạn gói miễn phí (RAM 512 MB) mà vẫn giữ trích dẫn và lọc theo ngày
  • Bảo mật khóa API, mật khẩu cơ sở dữ liệu; tự động triển khai; theo dõi chi phí bằng 0

3. Chọn dịch vụ cloud (mục 2 của báo cáo)

Tiêu chí theo yêu cầu của thầy: nhà cung cấp vừa và nhỏ, cho dùng thử, phù hợp bài toán, tránh phải nhập thẻ. Bảng dưới tổng hợp điều khoản gói miễn phí kiểm tra ngày 19/10/2026; các nhà cung cấp có thể thay đổi, nên kiểm tra lại khi tạo tài khoản.

Trong báo cáo, mục "Dịch vụ được lựa chọn": trình bày Render là dịch vụ chính (thông tin cơ bản, giao diện dashboard sau khi đăng nhập, các chức năng: Web Service, Static Site, Environment, Logs, Metrics, Events). Supabase và AuraDB trình bày ngắn ở tiểu mục "dịch vụ dữ liệu đi kèm".

Lý do phù hợp: ứng dụng web có backend Python và frontend tĩnh, đúng loại ứng dụng Render hỗ trợ; dữ liệu cần cả vector lẫn đồ thị, đúng hai dịch vụ dữ liệu được chọn; Render, Supabase, AuraDB không cần thẻ, còn OpenRouter là credit trả trước có hạn mức theo key, nên đáp ứng yêu cầu kiểm soát chi phí.

4. Kiến trúc triển khai

Phần nặng (đọc văn bản, tách Điều/Khoản, tính embedding cho kho văn bản) chạy một lần trên máy của nhóm. Máy chủ cloud chỉ làm phần nhẹ: nhận câu hỏi, truy xuất, gọi OpenRouter để mã hóa câu hỏi, rerank và sinh câu trả lời.

7. Các bước triển khai chi tiết (mục 5 của báo cáo)

Đây là phần chiếm nhiều trang nhất và được demo trực tiếp. Chụp ảnh ngay lúc làm, vì một số màn hình chỉ hiện một lần (ví dụ mật khẩu AuraDB). Che API key và mật khẩu trong ảnh trước khi đưa vào báo cáo.

  1. Chuẩn bị mã nguồn trên GitHub TV1

    Đẩy thư mục Code/graphrag-luat-giao-thong (đã có sẵn backend/, frontend/, .gitignore loại trừ mọi file .env) lên một repo chung. Mời 2 thành viên còn lại làm collaborator. GitHub Actions tự chạy kiểm thử mỗi lần push.

    Ảnh: trang repo, cấu trúc thư mục.

  2. Tạo cơ sở dữ liệu Supabase TV2

    New project, chọn khu vực Singapore cho gần Việt Nam, đặt mật khẩu cơ sở dữ liệu. Vào Database → Extensions bật vector. Mở SQL Editor, chạy db/schema.sql (cột embedding vector(1024) cho bge-m3). Lấy chuỗi kết nối loại pooler trong mục Connect (kết nối trực tiếp của Supabase có thể chỉ hỗ trợ IPv6).

    Ảnh: màn hình tạo project, extension vector đã bật, Table Editor có 2 bảng, mục Connect (che mật khẩu).

  3. Tạo đồ thị trên Neo4j AuraDB Free TV2

    Tạo instance Free. Tải ngay file thông tin đăng nhập (mật khẩu chỉ hiện một lần). Mở Query, chạy neo4j_constraints.cypher.

    Ảnh: console Aura, instance trạng thái Running, kết quả chạy ràng buộc.

  4. Tạo API key OpenRouter cho bản cloud TV1

    Trong trang Keys của OpenRouter, tạo một key riêng cho bản triển khai (không dùng chung key chạy thực nghiệm), đặt hạn mức chi tiêu nhỏ (credit limit) và không bật tự động nạp thêm tiền. Nếu key bị lộ, chỉ cần vô hiệu hóa key này.

    Ảnh: trang Keys (che key) với hạn mức đã đặt; trang Activity hiển thị lượt gọi và chi phí.

  5. Nạp dữ liệu từ máy của nhóm TV2

    Điền chuỗi kết nối cloud vào .env.cloud trên máy, chạy python scripts/03_embed.py --env cloud rồi python scripts/04_load.py --env cloud. Kiểm tra số bản ghi và số cạnh.

    Ảnh: terminal báo số node/cạnh, bảng don_vi trên Supabase, đồ thị một điều luật trong Aura.

  6. Triển khai backend: Render Web Service TV1

    New → Web Service → kết nối GitHub → chọn repo, Language Docker, Root Directory để trống, Dockerfile Path ./backend/Dockerfile, Docker Build Context ., Instance Type Free, khu vực Singapore, Health Check Path /health. Khai báo các biến trong .env.cloud.example. Chờ log build xong, mở /health rồi /health/db (kiểm tra kết nối Supabase, AuraDB).

    Ảnh: từng màn hình cấu hình, mục Environment (che giá trị), log build, kết quả /health, trang /docs của FastAPI.

  7. Triển khai frontend: Render Static Site TV3

    New → Static Site → cùng repo, Root Directory frontend, Build Command npm ci && npm run build, Publish Directory dist, biến VITE_API_URL trỏ tới địa chỉ backend. Sau đó đặt CORS_ORIGINS của backend bằng địa chỉ trang này.

    Ảnh: màn hình cấu hình, log build, trang chủ chạy trên địa chỉ public.

  8. Kết nối, kiểm thử và tự động triển khai Cả nhóm

    Cho phép địa chỉ frontend trong cấu hình CORS của backend. Thử đủ 5 chức năng từ điện thoại. Sửa một dòng chữ, push lên GitHub, xem Render tự deploy bản mới.

    Ảnh: tab Events của Render với các lần deploy, giao diện trên điện thoại.

  9. Giám sát và kiểm soát chi phí TV3

    Mỗi tuần mở trang mức sử dụng của Render (giờ chạy, băng thông), Supabase (dung lượng), Aura, OpenRouter (trang Activity: số lượt gọi, chi phí còn lại của key); ghi vào nhật ký nhóm.

    Ảnh: Render Metrics và Logs, trang Usage của Supabase, trang Billing của Render hiển thị 0 USD, chi phí OpenRouter của key cloud.

8. Kiểm soát chi phí và an toàn

Quy tắc của nhóm

  • Không nhập thẻ cho Render, Supabase, AuraDB. Nếu màn hình đòi thẻ, dừng lại và báo cả nhóm.
  • OpenRouter: dùng key riêng có hạn mức chi tiêu cho bản cloud, không bật tự động nạp tiền; bản công khai giới hạn 800 token đầu ra mỗi câu trả lời.
  • Không đưa .env, mật khẩu, API key lên GitHub. Nếu lỡ lộ, thu hồi key và đổi mật khẩu ngay.
  • Xem hết video hoặc tài liệu hướng dẫn trước khi làm theo (theo yêu cầu của thầy), lưu đường dẫn hướng dẫn để đưa vào tài liệu tham khảo.

Giới hạn cần nhớ trước buổi demo

  • AuraDB tự tạm dừng sau 3 ngày không dùng: mở console và bấm Resume trước buổi demo một ngày.
  • Supabase có thể tạm dừng sau 7 ngày ít hoạt động: mở dashboard kiểm tra trước.
  • Render tắt sau 15 phút không truy cập: mở trang web 2–3 phút trước khi trình bày.
  • Render cho 750 giờ/tháng mỗi workspace: đủ cho một web service chạy cả tháng.
